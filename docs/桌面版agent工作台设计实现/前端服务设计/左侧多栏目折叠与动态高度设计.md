# 左侧多栏目折叠与动态高度设计

## 1. 设计目标

AgentForge Desktop 左侧会话区同时包含置顶任务、任务和工作空间三类栏目。栏目高度不应使用固定百分比，否则会出现以下问题：

- 只有一条置顶任务时仍占据大片空白。
- 某栏目展开后把其他栏目挤到底部。
- 视觉上看似某栏目被自动收拢，实际上是内容区被 Flex 压缩为零。
- 内容较多时整个侧边栏滚动，用户无法同时看到三个栏目标题。

本设计的目标是：

1. 收拢栏目只保留标题高度。
2. 展开栏目按内容自然高度展示。
3. 内容总高度超出可用区域时，栏目内部独立滚动。
4. 置顶任务、任务、工作空间的展开状态相互独立，不使用互斥手风琴。
5. 已展开的置顶任务不能被长任务列表挤没。

## 2. 栏目结构

左侧会话区使用以下顺序：

```text
置顶任务
任务
工作空间
```

对应 Vue 状态：

| 栏目 | 展开状态 | 内容来源 |
| --- | --- | --- |
| 置顶任务 | `pinnedTasksOpen` | `pinnedTaskSessions` |
| 任务 | `normalTasksOpen` | `normalTaskSessions` |
| 工作空间 | `workspaceOpen` | `workspaceGroups` |

工作空间内部还有第二层展开状态 `expandedWorkspaceIds`，用于控制具体工作空间文件夹下的会话列表。

## 3. DOM 实现

每个栏目由标题和内容区两部分组成：

```vue
<section
  class="session-list-panel normal-task-panel"
  :class="{ 'is-collapsed': !normalTasksOpen }"
>
  <button class="task-group-title" @click="normalTasksOpen = !normalTasksOpen">
    <span>任务 ({{ normalTaskSessions.length }})</span>
    <i :class="normalTasksOpen ? 'el-icon-arrow-down' : 'el-icon-arrow-right'" />
  </button>

  <div v-show="normalTasksOpen" class="session-panel-body">
    <!-- 会话条目 -->
  </div>
</section>
```

这里使用 `v-show` 而不是 `v-if`，使栏目重新展开时保留内部 DOM 和滚动上下文。

## 4. 动态高度策略

### 4.1 外层容器

```css
.session-scroll {
  flex: 1;
  min-height: 0;
  overflow: hidden;
  display: flex;
  flex-direction: column;
}
```

`min-height: 0` 是关键设置。Flex 子项默认使用内容最小高度，如果不设置为零，内容较多时子项会撑开整个侧边栏。

### 4.2 展开栏目

```css
.session-list-panel {
  display: flex;
  flex: 0 1 auto;
  min-height: 0;
  max-height: 100%;
  flex-direction: column;
  overflow: hidden;
}
```

`flex: 0 1 auto` 的含义：

- `flex-grow: 0`：内容较少时不强制填充剩余空间。
- `flex-shrink: 1`：内容总高度超限时允许栏目收缩。
- `flex-basis: auto`：优先使用内容的自然高度。

因此，只有一条会话时栏目只占用一条会话的高度，不会产生大片空白。

### 4.3 收拢栏目

```css
.session-list-panel.is-collapsed {
  flex: 0 0 auto;
  min-height: 0;
  max-height: none;
}
```

收拢状态禁止增长和收缩，栏目高度完全由标题决定。这保证下一个栏目会紧跟其后，而不是停留在侧边栏底部。

### 4.4 内部滚动

```css
.session-panel-body {
  flex: 0 1 auto;
  min-height: 0;
  overflow-y: auto;
  overscroll-behavior: contain;
}
```

内容区使用自然高度；当父栏目因整体空间不足而收缩时，内容区出现自己的纵向滚动条。`overscroll-behavior: contain` 防止滚动到顶部或底部时继续带动外层页面。

## 5. 置顶任务保护

置顶任务通常数量较少，应保持稳定可见，不能在展开任务列表后被压缩为零。

```css
.pinned-task-panel {
  flex: 0 0 auto;
  max-height: 35%;
}
```

该规则衩示：

- 置顶任务数量较少时，使用自然高度。
- 展开普通任务不会把置顶内容挤没。
- 置顶任务较多时，最多占会话区域的 35%，多余内容在栏目内部滚动。

## 6. 状态独立性

三个栏目不实现“展开一个后自动收拢其他栏目”的逻辑。点击标题时只修改当前栏目的 Boolean 状态：

```js
pinnedTasksOpen = !pinnedTasksOpen
normalTasksOpen = !normalTasksOpen
workspaceOpen = !workspaceOpen
```

如果某栏目在其他栏目展开后“看起来被收拢”，应首先检查 CSS Flex 收缩，不应通过增加状态联动解决。

## 7. 栏目顺序

顺序通过 CSS `order` 统一控制：

```css
.pinned-task-panel { order: 1; }
.normal-task-panel { order: 2; }
.workspace-session-section { order: 3; }
```

即使后续调整 Template 中的 DOM 位置，也应保持用户看到的顺序稳定。

## 8. 会话条目布局

会话条目使用单行布局：左侧标题，右侧相对时间。操作按钮使用绝对定位，避免鼠标悬浮时参与 Flex 宽度重算并产生“撑开”效果。

```css
.session-body {
  padding-right: 48px;
}

.session-time,
.session-more,
.session-pin-action {
  position: absolute;
  top: 50%;
  transform: translateY(-50%);
}
```

常态显示相对时间，悬浮时时间隐藏，同一块预留区域内显示“更多”和“置顶/取消置顶”操作，条目高度和宽度均不变。

## 9. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 三个栏目全部收拢 | 三个标题连续排列，不留额外空白 |
| 只展开一条置顶任务 | 置顶栏目按一条内容的自然高度显示 |
| 置顶任务和任务同时展开 | 两者同时可见，不修改对方展开状态 |
| 任务数量较多 | 任务内容区独立滚动，工作空间标题仍可见 |
| 其他栏目收拢、工作空间展开 | 工作空间按内容展开，超出可用高度后内部滚动 |
| 悬浮会话条目 | 时间切换为操作按钮，条目不伸缩、不抖动 |
