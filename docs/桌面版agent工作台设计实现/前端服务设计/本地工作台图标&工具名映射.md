# 本地工作台图标与工具名映射

## 1. 设计目标

本地工作台在展示 Agent Loop 中间过程时，应优先向用户表达“当前正在做什么”，而不是直接暴露底层工具的技术名称。

图标用于快速识别工具类型，文案则优先展示工具调用的意图。当缺少意图描述时，才回退展示原始工具名。

## 2. 工具行展示规则

优雅模式下的工具行按以下规则渲染：

1. **工具展示名称始终显示**：由 `toolMeta.js` 映射为业务语义名称（如 `read` → 「读取文件」），未映射时才回退原始 `toolName`。
2. 解析工具入参中的 `__thought` 字段，并兼容 `_thought` 字段；存在且非空时，作为次级说明追加在工具名之后，以 `·` 分隔。
3. `__thought` 不存在、为空或入参无法解析时，只显示工具展示名称，不出现分隔符。
4. 工具完成后显示耗时；执行中显示加载状态。
5. 点击工具行仍可展开查看返回结果，工具名与意图文案都不影响详情查看。

示例：

| 工具名 | `__thought` | 主界面展示 |
| --- | --- | --- |
| `bash` | `查看当前工作空间根目录内容` | 终端图标 + `执行命令` · `查看当前工作空间根目录内容` + 耗时 |
| `bash` | 空 | 终端图标 + `执行命令` + 耗时 |
| `glob` | `搜索项目中的配置文件` | 查找文件图标 + `查找文件` · `搜索项目中的配置文件` + 耗时 |
| `read_resource` | 空（该工具未注入 `__thought`） | 读取资源图标 + `读取资源` + 耗时 |
| `read` | `读取图标映射设计文档` | 文档页图标 + `读取文件` · `读取图标映射设计文档` + 耗时 |

## 3. 工具清单与渲染映射总览

本章按“工具 → 入参 → 图标 → 发布模式渲染”四个维度各列一张表，作为当前实现的事实基线。数据来源：

- 运行时工具：`agentforge-harness-agent` 的 `LocalRuntimeTools`（`read` / `write` / `edit` / `glob` / `grep` / `rg` / `bash`）；
- 桌面端扩展工具：`DesktopSkillTool`（`skill`）、`DesktopReadResourceTool`（`read_resource`）；
- 框架治理工具：`AskUserTool`（`ask_user`），在 `PermissionInterruptModule` 开启 `enableAskUser()` 后由 `ReActAgent` 注册。

### 3.1 后端工具总览

| 工具名 | 注册位置 | 用途 | 入参 | `__thought` | 图标（完成态） | 发布模式主界面渲染 |
| --- | --- | --- | --- | --- | --- | --- |
| `read` | `LocalRuntimeTools.read` | 读取工作区 UTF-8 文本文件，带行号 | `path` | 注入 | 文档页 `read` | 文档页图标 + `读取文件` · 意图文案 + 耗时 |
| `write` | `LocalRuntimeTools.write` | 新建或覆盖工作区文件（已存在文件须先读） | `path`、`content` | 注入 | 页面+笔 `write` | 页面+笔图标 + `写入文件` · 意图文案 + 耗时 |
| `edit` | `LocalRuntimeTools.edit` | 在已读文件中替换唯一命中的文本 | `path`、`oldText`、`newText` | 注入 | 铅笔 `edit` | 铅笔图标 + `编辑文件` · 意图文案 + 耗时 |
| `glob` | `LocalRuntimeTools.glob` | 按 glob 模式查找工作区文件 | `pattern` | 注入 | 文件夹+放大镜 `glob` | 文件夹+放大镜图标 + `查找文件` · 意图文案 + 耗时 |
| `grep` | `LocalRuntimeTools.grep` | 用 Java 正则搜索工作区文件内容 | `regex`、`path` | 注入 | 放大镜+文本线 `grep` | 放大镜+文本线图标 + `搜索内容` · 意图文案 + 耗时 |
| `rg` | `LocalRuntimeTools.rg` | 调用 ripgrep 搜索工作区并返回命中行 | `pattern`、`path` | 注入 | 放大镜+闪电 `rg` | 放大镜+闪电图标 + `快速搜索` · 意图文案 + 耗时 |
| `bash` | `LocalRuntimeTools.bash` | 在工作区执行前台 shell 命令 | `command` | 注入 | 终端窗口 + `>_` `terminal` | 终端图标 + `执行命令` · 意图文案 + 耗时 |
| `skill` | `DesktopSkillTool.skill` | 读取 Skill 索引中某个 Skill 的完整 `SKILL.md` | `path` | 未注入 | 六边形+星标 `skill` | 六边形+星标图标 + `加载技能` + 耗时（无意图文案） |
| `read_resource` | `DesktopReadResourceTool.read` | 读取本机绝对路径或 http/https 链接（图片转多模态附件） | `paths`、`hint`（可选） | 未注入 | 页面+回形针 `resource` | 页面+回形针图标 + `读取资源` + 耗时（无意图文案） |
| `ask_user` | `AskUserTool.ask`（`ReActAgent` 注册） | 向用户提出单选 / 多选 / 填空问题，等待作答后再继续 | `questions`、`reason`（可选）、`submitLabel`（可选） | 未注入 | 不产生工具行（`ask` 备用） | 渲染为中断卡片“等待用户确认”，不走工具行 |

补充说明：

1. `__thought` 的注入由 `LocalToolFactory.buildLocalToolsWithThought(..., true)` 完成，`HarnessAgent` 只对 **runtime 工具** 开启；`additionalTool(...)` 注册的 `skill`、`read_resource` 走不带注入的分支，`AskUserTool` 也由 `ToolService.tools(...)` 直接注册。实际对话中这三者没有意图文案，工具行只显示映射后的展示名称；若模型自行携带 `_thought` / `__thought`（前端两者都兼容），则追加显示为次级说明。
2. 当前桌面端未接入 `todoplan`、MCP 与 HTTP 插件工具；这些工具若后续接入，会以 `additionalTool` 形式出现，默认落到兜底扳手图标与原始工具名，需要时在 `toolMeta.js` 补登记即可自动获得图标与中文名。
3. `grep` / `rg` 的 `path` 在 schema 上必填，但实现允许为空并回退到工作区根目录。

### 3.2 入参明细

一个工具占一行，参数全部内联在同一单元格；`必填` / `可选` 取自 `@P` 注解（`required` 默认为 `true`）。

| 工具名 | 参数（名称: 类型 / 是否必填） | 约束与说明 |
| --- | --- | --- |
| `read` | `path`: string / 必填 | 工作区相对路径 |
| `write` | `path`: string / 必填 · `content`: string / 必填 | `content` 为完整 UTF-8 内容，写入即整体覆盖，已存在文件须先 `read` |
| `edit` | `path`: string / 必填 · `oldText`: string / 必填 · `newText`: string / 必填 | 文件须先 `read`；`oldText` 必须唯一命中，`newText` 可为空串 |
| `glob` | `pattern`: string / 必填 | 相对工作区的 glob，如 `**/*.java` |
| `grep` | `regex`: string / 必填 · `path`: string / 必填 | `regex` 为 Java 正则；`path` 为文件或目录，空值回退 `.` |
| `rg` | `pattern`: string / 必填 · `path`: string / 必填 | `pattern` 为 ripgrep 模式；`path` 为工作区相对搜索路径，空值回退 `.` |
| `bash` | `command`: string / 必填 | 前台命令，超时 5 分钟，不支持后台任务 |
| `skill` | `path`: string / 必填 | Skill 目录或其 `SKILL.md` 路径，取自注入的 Skill 索引 |
| `read_resource` | `paths`: string[] / 必填 · `hint`: string / 可选 | `paths` 为 1–5 个本机绝对路径或 http/https URL；`hint` 说明为何需要这些资源 |
| `ask_user` | `questions`: object[] / 必填 · `reason`: string / 可选 · `submitLabel`: string / 可选 | `questions` 为 1–10 个问题；`reason` 即卡片副标题；`submitLabel` 省略时前端默认“确认并继续”。问题项字段：`id`、`title`、`type` 必填，`description`、`required`、`options`、`minSelections`、`maxSelections`、`maxLength`（≤4000）、`placeholder` 可选，`options` 仅选择题使用 |

所有工具在执行时还会额外收到框架注入的 `__thought`（必填字符串），执行器会忽略未在方法签名中声明的额外参数。

### 3.3 图标资源清单（已落地）

统一规格：`24×24` viewBox、`stroke="currentColor"`、`fill="none"`、渲染尺寸 `15×15`；除终端图标保持原有配色 `#7891b2` 外，其余均继承 `.elegant-tool-icon` 的 `#91a0b6`。

| 图标标识 | 展示名称 | SVG 图形 | 适用工具 | 实现位置 |
| --- | --- | --- | --- | --- |
| `terminal` | 执行命令 | 圆角矩形窗口 + `>_` 折线（`stroke-width` 1.7） | `bash` 及命中终端关键字的自定义工具 | `ElegantToolItem.vue` `iconKey === 'terminal'`，**保持历史基线不变** |
| `read` | 读取文件 | 页面轮廓 + 右上折角 + 两条正文线 | `read` | `iconKey === 'read'` |
| `write` | 写入文件 | 闭合页面 + 两条正文线 + 纸外斜向笔 | `write` | `iconKey === 'write'` |
| `edit` | 编辑文件 | 斜置铅笔 + 笔头分隔线 | `edit` | `iconKey === 'edit'` |
| `glob` | 查找文件 | 文件夹 + 内嵌放大镜（含手柄） | `glob` | `iconKey === 'glob'` |
| `grep` | 搜索内容 | 放大镜 + 镜内两条文本线 | `grep` | `iconKey === 'grep'` |
| `rg` | 快速搜索 | 放大镜 + 镜内闪电 | `rg` | `iconKey === 'rg'` |
| `resource` | 读取资源 | 页面 + 折角 + 回形针 | `read_resource` | `iconKey === 'resource'` |
| `skill` | 加载技能 | 六边形 + 五角星 | `skill` | `iconKey === 'skill'` |
| `ask` | 询问确认 | 对话气泡 + 问号 | `ask_user`（当前由中断卡片承载，图标为备用） | `iconKey === 'ask'` |
| `tool` | 原始工具名 | 通用扳手（`stroke-width` 1.8） | 未命中任何映射的工具 | `v-else` 兜底分支 |

设计约束：

1. 图标全部内联在组件中，没有独立 `.svg` 资源文件；不采用“图标文件 + 动态 import”，避免 Electron 打包后的本地加载差异。
2. `read` / `write` / `edit` 共用“页面轮廓”视觉母题，靠正文线、笔尖、铅笔区分动作；`grep` / `rg` 共用放大镜主体，靠镜内“文本线 / 闪电”区分。
3. 执行中一律使用加载图标，不显示静态图标，避免误导用户认为操作已完成。
4. 状态差异只靠 `currentColor` 与 `.elegant-tool.done` 类切换，不新增硬编码色值。

| 完成 · 读资源 | `read_resource` | 页面 + 回形针图标 + `读取资源` + `（耗时）` | 资源元数据 JSON；图片由 `ReadArtifactMiddleware` 转多模态附件 |
| 完成 · 加载技能 | `skill` | 六边形 + 星标图标 + `加载技能` + `（耗时）` | `SKILL.md` 正文 |

| `bash` 高风险命令 | `ShellCommandPermissionRule` 命中 `rm` / `sudo` / `dd` / `mkfs` 等 | 不出现工具行，改为输入框上方审批卡片（`InterruptCard` + `PermissionApprovalStep`） | 折叠的“调用参数”原文；批准后恢复执行才补出终端图标行 |

| 调试模式对照 | 渲染模式切到“调试模式 · 事件时间线” | `ToolCard` 展示 `toolName`、`methodName`、执行状态、耗时徽标 | `入参` + `结果` 两段 JSON，附带 `toolCallId` 与调用时间 |

保持不变的部分：

1. 耗时格式：`<1000ms` 显示 `xxxms`，否则 `x.xs`。
2. 展开/收起交互与“结果”区块结构不变。
3. `bash` 终端图标的图形、配色与判定关键字不变。
4. `ask_user` 仍由中断卡片承载，未改为工具行（`ask` 图标暂为备用）。

### 3.5 图标与工具名映射实现说明

> 本节记录 3.3 / 3.4 的落地方式与实现约束；3.3、3.4 为最终事实。

#### 3.5.1 实施目标

1. **`bash` 图标保持不变**：继续使用现有“终端窗口 + `>_`”SVG，判定关键字、配色与 `elegant-tool-terminal` 类名全部沿用，避免已发布版本的视觉回退。
2. **其余工具新建专用 SVG**：不再统一复用通用扳手，按“读 / 写 / 改 / 找文件 / 搜内容 / 读资源 / 加载技能”拆分，使用户不展开详情也能分辨动作类型。
3. **工具名映射为用户可理解名称**：工具展示名称始终显示，用业务语义名称替代底层技术名（如 `read` 显示「读取文件」）；`__thought` 存在时作为次级说明追加在其后。

#### 3.5.2 图标实现要点

统一规格：`24×24` viewBox、`fill="none"`、`stroke="currentColor"`、`stroke-width` 1.3–1.8、渲染尺寸 `15×15`。

| 图标 | 结构拆解 | 设计意图 |
| --- | --- | --- |
| 终端 | 圆角矩形 + `>_` 折线 | 沿用历史基线，不重新设计 |
| 读取文件 | 页面轮廓 + 折角 + 两条正文线 | 一眼识别“只读、不改动” |
| 写入文件 | 闭合页面 + 正文线 + 纸外斜笔 | 与 `edit` 区分：笔在纸外表示新建/整体写入 |
| 编辑文件 | 斜置铅笔 + 笔头分隔线 | 只有笔，无页面，表示局部改写 |
| 查找文件 | 文件夹 + 内嵌放大镜 | 放大镜落在文件夹内部，避免压住边框 |
| 搜索内容 | 放大镜 + 镜内两条文本线 | 强调“搜文本内容”而非文件名 |
| 快速搜索 | 放大镜 + 镜内闪电 | 与 `grep` 靠“闪电=高性能”区分 |
| 读取资源 | 页面 + 折角 + 回形针 | 回形针表达“附加/引用的外部资源” |
| 加载技能 | 六边形 + 五角星 | 六边形作为“能力模块”载体 |
| 询问确认 | 对话气泡 + 问号 | 备用，与中断卡片语义一致 |
| 兜底 | 通用扳手 | 未映射工具的最后一层兜底 |

实现约束：

1. 图标全部内联在 `ElegantToolItem.vue` 的独立 `v-if` 分支中，不采用“图标文件 + 动态 import”，避免 Electron 打包后的本地加载差异。
2. `read` / `write` / `edit` 共用“页面 + 笔”视觉母题，`grep` / `rg` 共用放大镜主体，通过内部元素区分，保证同一族图标风格统一。
3. 所有新图标只使用 `currentColor`，不引入硬编码色值；完成态与执行态色差由 `.elegant-tool.done` 统一控制。
4. 执行中一律显示加载图标，静态图标只在 `isFinish === true` 时出现。

#### 3.5.3 工具名映射实现

映射集中在 `agentforge-desktop-ui/src/constants/toolMeta.js`，同时导出 `label`（展示名称）与 `iconKey`（图标标识）。

| 工具名 | 展示名称 | 图标标识 |
| --- | --- | --- |
| `read` | 读取文件 | `read` |
| `write` | 写入文件 | `write` |
| `edit` | 编辑文件 | `edit` |
| `glob` | 查找文件 | `glob` |
| `grep` | 搜索内容 | `grep` |
| `rg` | 快速搜索 | `rg` |
| `bash` | 执行命令 | `terminal` |
| `skill` | 加载技能 | `skill` |
| `read_resource` | 读取资源 | `resource` |
| `ask_user` | 询问确认 | `ask` |
| 其他 | 原始 `toolName` | `tool` |

解析规则：

1. 大小写不敏感；`READ`、`Read_Resource` 均能命中。
2. 带命名空间的工具名按末段匹配：`mcp__fs__read` → `read`，`server.tool/grep` → `grep`。
3. 未登记但命中终端关键字的工具（如 `exec_command`、`shell`）沿用终端图标，展示名称统一收敛为「执行命令」，不暴露 shell 术语。
4. 完全未命中时回退原始 `toolName`，保证未知工具仍可追踪。
5. 展示名称仅影响工具行渲染，不参与搜索、不写入消息内容。

### 3.6 全工具覆盖测试用例

发布模式下要一次性验证全部工具行的图标与展示名称，可用下面这一句提问；它会按顺序触发 10 个工具。

**标准用例（一句话）：**

> 请在当前工作空间依次调用全部工具做一次演示：先用 glob 找 `**/*.md`，再用 grep 和 rg 分别搜一次 `AgentForge`，然后 read 其中一个 md 文件，接着 write 一个 `.tmp/tool-demo.md` 并 edit 它补一行，再 bash 跑一次 `ls`，用 skill 加载 code-archaeology-skill，用 read_resource 读取 `/Users/edy/changlu_workspace/mymd/我的开源项目/AgentForge-Desktop/README.md`，最后用 ask_user 问我演示是否通过。

用例片段与预期表现的对照：

| 片段 | 触发工具 | 预期图标 | 预期展示名称 | 展开内容 |
| --- | --- | --- | --- | --- |
| 用 glob 找 `**/*.md` | `glob` | 文件夹 + 放大镜 | 查找文件 | 命中文件列表 |
| 用 grep 搜 `AgentForge` | `grep` | 放大镜 + 文本线 | 搜索内容 | `文件:行号:内容` 列表 |
| 用 rg 搜 `AgentForge` | `rg` | 放大镜 + 闪电 | 快速搜索 | `文件:行号:内容` 列表 |
| read 其中一个 md | `read` | 页面 + 折角 | 读取文件 | 带行号的文件内容 |
| write `.tmp/tool-demo.md` | `write` | 页面 + 笔 | 写入文件 | `Wrote N bytes to ...` |
| edit 补一行 | `edit` | 铅笔 | 编辑文件 | `Edited ...` |
| bash 跑 `ls` | `bash` | 终端窗口（不变） | 执行命令 | 目录列表 |
| skill 加载 index | `skill` | 六边形 + 星标 | 加载技能 | `SKILL.md` 正文 |
| read_resource 读 README | `read_resource` | 页面 + 回形针 | 读取资源 | 资源元数据 JSON |
| ask_user 问是否通过 | `ask_user` | 不产生工具行 | — | 输入框上方中断卡片 |

使用约束：

1. **`ask_user` 只能验证中断卡片，不能验证工具行**：框架要求它单独调用并暂停执行，因此 `ask` 图标在本次用例中仍为备用状态。
2. **`write` 必须指向新建文件**：目标已存在且未先 `read` 时会报 `FILE_NOT_READ`。用 `.tmp/tool-demo.md` 这类新路径即可；`write` 后该文件自动登记为已读，紧随其后的 `edit` 无需再 `read`。
3. **`bash` 要用安全命令**：`ls` 不触发审批；换成 `rm`、`sudo`、`dd` 等会弹出审批卡片，工具行要等批准后才补出，演示节奏会被打断。
4. **`read_resource` 必须给绝对路径或 http 链接**：相对路径会失败，故用例中写死本机绝对路径。
5. **`skill` 的 path 必须取自注入的 Skill 索引**：直接填 `code-archaeology-skill` 时，模型应按索引匹配到完整路径再传入。

若模型倾向把多个工具并发批处理、导致工具行顺序错乱，可拆成两句执行，保证每步只调一个工具：

> 第一句：先 glob 找 `**/*.md`，再 grep 和 rg 各搜一次 `AgentForge`，然后 read 一个 md 文件、write 并 edit `.tmp/tool-demo.md`，最后 bash 跑 `ls`——每步只调一个工具。
>
> 第二句：再 skill 加载 code-archaeology-skill、read_resource 读本机 README.md，最后 ask_user 问我是否通过。

验收要点：

1. 9 个工具行（除 `ask_user`）的图标、展示名称、耗时与本表一致。
2. `bash` 工具行图标与改造前完全一致，无视觉回退。
3. 所有工具行在执行中显示加载图标，完成后才切换为静态图标。
4. 传入 `__thought` 时，工具名仍照常显示，意图文案以 `·` 分隔追加在其后，两者不互相顶替。
5. `.tmp/tool-demo.md` 属测试产物，用例结束后应清理。

## 4. 图标映射

### 4.1 命令终端类

工具名转为小写后，包含下列任一关键字时，使用“终端窗口 + `>_`” SVG 图标：

- `bash`
- `shell`
- `terminal`
- `exec_command`
- `command`

终端图标使用 `currentColor` 继承工作台主题色，完成态使用低饱和蓝灰色，与过程文字层级保持一致。

### 4.2 其他工具

未命中专用图标映射的工具，完成后使用通用扳手 SVG 图标兜底。判定顺序为：先按 `toolMeta.js` 的 `iconKey` 精确匹配专用图标，再按终端关键字匹配 `terminal`，最后落到兜底扳手。

执行中的所有工具统一使用加载图标，避免静态图标误导用户认为操作已完成。

## 5. 实现位置

- 工具行组件：`agentforge-desktop-ui/src/modes/elegant/ElegantToolItem.vue`
- 意图参数名：优先使用 `__thought`，同时兼容 `_thought`
- 工具元信息与归一分发：`agentforge-desktop-ui/src/constants/toolMeta.js`（`TOOL_META`、`resolveToolKey`、`toolIconKey`、`toolLabel`）
- 图标分发计算属性：`iconKey`（`ElegantToolItem.vue`）
- 展示名称计算属性：`displayName`（`ElegantToolItem.vue`）
- 意图文案计算属性：`thought`（`ElegantToolItem.vue`）
- 工具事件来源：`ServiceStreamingMiddleware` 与 `SessionLifecycleMiddleware`，均以 `tool_card` 形式推送 `toolName` / `inputParams` / `outputResult` / `duration`
- 工具注册入口：`AgentRuntimeService#build`（`additionalTool`）+ `HarnessAgent` 构造（runtime 工具，含 `__thought` 注入）

## 6. 扩展约定

1. 新增工具专用图标时，优先在组件内建立类型判定，不应在模板中散落多组字符串判断。
2. SVG 应使用 `currentColor`，便于主题、状态和深浅色模式统一调整。
3. 工具展示名称与 `__thought` 是并列关系：名称始终显示用于识别工具，`__thought` 作为次级说明补充意图，不互相替代。
4. `__thought` 属于用户可见的过程摘要，内容应简洁、明确，不应包含密钥、完整命令入参或其他敏感信息。
