# 前端打包配置设计

> 状态：已接入统一打包配置；已验证 macOS 应用包图标和两平台图标格式转换，Windows 安装包仍需在 Windows 环境验证。

## 1. 目标

为桌面安装包提供统一的自定义配置入口，配置文件及其资源集中存放在 `agentforge-desktop-ui/scripts/conf`。支持通过 `appLogo` 设置应用图标，通过 `appName` 设置安装后的应用名称；默认使用当前页面图标和 `AgentForge Desktop` 名称。

配置在打包时读取并固化到产物中。更换配置或图片后需要重新打包、安装；它不是安装后可动态修改的用户设置。

## 2. 当前现状

- `agentforge-desktop-ui/index.html` 的页面图标引用 `public/logo.png`，尺寸为 1254 × 1254 PNG，可作为默认图标源文件。
- 应用界面左上角导航栏 `src/components/AppNavRail.vue` 当前显示的是文字 `AF`，不是图片。页面标签图标、导航栏文字和操作系统安装后的应用图标是不同位置；本方案默认图片暂按页面图标 `public/logo.png` 理解，供评审确认。
- 原有 electron-builder 配置未指定应用图标；现由统一打包脚本传入配置的图标和应用名称。
- 各平台最终通过 `scripts/package/package-desktop.mjs` 调用 electron-builder，该脚本是统一注入打包配置的合适位置。

## 3. 目录与配置

当前目录：

```text
agentforge-desktop-ui/scripts/conf/
├── package.json              # 打包自定义配置，非项目的 npm package.json
└── assets/
    └── app-logo.png          # 从 public/logo.png 复制的默认图片
```

`package.json` 示例：

```json
{
  "appLogo": "assets/app-logo.png",
  "appName": "AgentForge Desktop"
}
```

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `appLogo` | string | `assets/app-logo.png` | 应用图标源文件路径，相对于配置文件所在目录 `scripts/conf` 解析 |
| `appName` | string | `AgentForge Desktop` | 打包产品名称，用于应用包及安装产物命名；支持中文和空格 |

配置文件和默认资源随源码提交。使用者可将自定义图片放入 `conf/assets`，修改 `appLogo` 后重新打包。为保证各平台一致，首期约定使用正方形 PNG，建议至少 1024 × 1024 像素并保留透明背景；不引入额外配置项。

配置缺失、`appName` 或 `appLogo` 未填写时使用各自默认值。`appName` 不能包含首尾空格、末尾句点、Windows 保留名称或 `<>:"/\\|?*` 等文件名非法字符；应用标识 `appId` 不变，界面中写死的标题也不会随之改变。

配置文件 JSON 无效、字段类型不正确、指定图片不存在、PNG 文件头不正确或尺寸小于 512 × 512 时，在服务端构建之前报错。PNG 的完整解码由 electron-builder 转换图标时检查。默认图片不存在时同样报错。

## 4. 打包接入设计

1. `package-desktop.mjs` 在服务端构建之前读取并校验 `scripts/conf/package.json`，以配置文件目录作为相对路径基准，得到图标绝对路径。绝对路径如需支持，应明确其仅适用于当前打包机器；推荐使用相对路径，以便团队复用。
2. 将经过校验的 PNG 路径通过 electron-builder 的 `--config.mac.icon` 或 `--config.win.icon` 传入对应目标平台。使用进程参数数组传递路径，避免空格和中文路径造成命令行拆分。
3. 由 electron-builder 的图标处理能力生成目标平台所需格式；实际项目版本和目标平台须通过真实打包验证。若该版本或平台不接受 PNG，应在打包准备阶段生成对应的 `.icns` / `.ico`，再传入生成文件，不改变用户配置的 `appLogo` 入口。
4. 保持现有 `package:current`、`package:mac`、`package:mac-arm64`、`package:mac-x64` 和 `package:win-x64` 等入口最终使用同一配置；无需分别维护平台图标配置。
5. 将 `appName` 通过 `--config.productName` 传给 electron-builder，影响应用包名称和使用 `${productName}` 的产物名称；`appId` 和版本号保持不变。`appLogo` 作用于操作系统层面的图标，不改变网页 favicon、导航栏或聊天头像。

数据流：

```text
scripts/conf/package.json
          │ appLogo（相对 conf 目录）
          ▼
scripts/conf/assets/app-logo.png
          │ 读取、校验并解析绝对路径
          ▼
package-desktop.mjs → electron-builder → 平台安装包 / 应用图标
```

PNG 是统一的输入源；Windows 安装程序图标及卸载程序图标是否随应用图标一致，应在实际 NSIS 产物中验证，必要时显式传递相应 electron-builder 配置。macOS Dock、Finder 和应用程序目录图标也应以实际安装结果为准。

## 5. 使用方式

默认打包时保留配置文件中的默认路径即可。自定义时：

1. 将符合要求的 PNG 放到 `agentforge-desktop-ui/scripts/conf/assets/`。
2. 按需修改 `scripts/conf/package.json` 中的 `appLogo`（例如 `assets/my-logo.png`）和 `appName`（例如 `AgentForge Studio`）。
3. 在 `agentforge-desktop-ui` 目录执行对应平台的现有打包命令，例如 macOS Apple Silicon 使用 `npm run package:mac-arm64`，Windows x64 使用 `npm run package:win-x64`。
4. 安装新产物后检查应用图标。系统可能缓存旧图标，必要时检查新生成的应用包内部资源并刷新系统图标缓存。

## 6. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 使用默认配置打包 | 安装后的应用图标使用 `conf/assets/app-logo.png`，图片内容与当前 `public/logo.png` 一致 |
| 使用自定义 PNG 打包 | 对应平台安装后的应用图标使用自定义图片 |
| 设置自定义 `appName` | 应用包和安装产物使用配置名称；macOS 应用包元数据使用该名称 |
| 未设置或留空 `appName` | 使用 `AgentForge Desktop` |
| 名称含非法文件名字符 | 服务端构建前报错并终止 |
| 路径包含空格或中文 | 能正确读取图片并完成打包 |
| 配置文件不存在或缺少 `appLogo` | 使用约定的默认图片；默认图片不存在时报错 |
| JSON 无效、类型错误、图片不存在或损坏 | 尽早输出包含配置位置和原因的错误，终止打包 |
| macOS 和 Windows 各自原生打包 | 检查平台产物中的图标及安装后的显示；Windows 同时检查安装程序和卸载程序图标 |
| 界面回归 | 页面 favicon、左侧 `AF` 标识及其他现有功能保持原状 |
